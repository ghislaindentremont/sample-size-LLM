The test and the sample size calculation

  
Domain experts rate each LLM response as acceptable or unacceptable, and the resulting proportion of acceptable LLM responses is tested against a pre-defined absolute performance threshold p₀. The test is one-sided: the null hypothesis is that the true proportion is at or below p₀ (H₀: p ≤ p₀); the alternative is that it exceeds p₀ (H₁: p > p₀). Both methods below reject H₀ when the number of acceptable responses X reaches a critical count c that depends on p₀, N, and α.

  
Wilson score test (recommended). The Wilson score method has better coverage than the Wald test and the Clopper-Pearson (exact) test.[1][2][3] The sample size calculation uses the normal-approximation score test formula:[4][5]

  
N = ⌈ ( z_α · √(p₀q₀)  +  z_β · √(p₁q₁) )² / (p₁ − p₀)² ⌉        q = 1 − p

  
The approximation is reliable when N·(1 − p₀) ≥ 10 — for p₀ = 0.90, N ≥ 100 — a condition met by the sample sizes required for 80% power at proportions typical of LLM evaluation. After data collection, conduct the test with the Wilson score method (in R, prop.test(X, N, p = p₀, alternative = "greater", correct = FALSE)).

  
Clopper-Pearson exact is shown for comparison. It evaluates P(X ≥ c | Binomial(N, p)) directly, guaranteeing a type I error rate at or below α; because the binomial is discrete, the achieved rate is usually below nominal and the test is somewhat conservative.






  
Assumptions

  

    
One LLM response per query, and query-response pairs are independent.
Each query-response pair is an independent Bernoulli trial. This requires that the LLM-based system produces sufficiently consistent responses for one response per query to be adequate (e.g., confirmed by assessing semantic repeatability a priori). If each query receives several LLM responses, use the multiple responses per query tab.

    
Each LLM response has one binary reference label.
If several domain experts rate the same response, their ratings must be combined into one pre-specified label (e.g., consensus, majority vote) before analysis; the unit of analysis is the query-response pair, not the individual rating. Rating criteria are defined before any responses are seen.

    
User queries are independent and randomly drawn from the population of potential queries for the use case.
If the queries are easier or differently distributed than those expected in the intended use context, the estimated proportion applies to the evaluation set, not to that context.

    
N is fixed before data collection.
Stopping early or adding query-response pairs based on interim results inflates the true type I error rate.

    
The primary analysis is this one-sided threshold test.
Failure to reject H₀ does not show that performance is below p₀. Comparative, equivalence, or non-inferiority questions require different tests and calculations.

Multiple LLM responses per query

  
Given the stochastic nature of LLM outputs, researchers may generate several LLM responses per user query. Queries differ in difficulty, so the k ratings for the same query are not independent: a difficult query tends to yield unacceptable responses every time, an easy one acceptable responses every time. Each query i has its own acceptability probability pi, modelled as pi ~ Beta(a, b), with Xi | pi ~ Binomial(k, pi) acceptable responses — a Beta Binomial distribution. The estimand is the overall proportion of acceptable LLM responses p = a/(a+b); the intra-query correlation ρ = 1/(a+b+1) measures how much queries differ in difficulty.

  
Treating the N × k ratings as independent understates their variance. The correct variance is larger by the variance inflation factor (VIF), a standard result for clustered binary outcomes:[6]

  
VIF = 1 + (k − 1)·ρ

  
so N × k LLM responses carry the information of only N × k / VIF independent query-response pairs. The calculator applies this correction to the Wilson score formulas of the first tab:

  
N_iid  = ( z_α·√(p₀q₀) + z_β·√(p₁q₁) )² / (p₁ − p₀)²   query-response pairs needed if independent
N      = ⌈ VIF · N_iid / k ⌉                            queries;   N × k total LLM responses
power  = Φ( ( (p₁ − p₀)·√(N·k/VIF) − z_α·√(p₀q₀) ) / √(p₁q₁) )
reject H₀ if  X ≥ ⌈ N·k·p₀ + z_α·√(N·k·p₀q₀·VIF) ⌉

  
ρ is treated as a known planning value. With k = 1, VIF = 1 for any ρ and the calculation reduces to the one-sample proportion test. The "uncorrected" column in the result panel shows what the one-sample formulas would report if the N × k responses were treated as independent, and what they would actually deliver: the uncorrected test's true type I error rate is 1 − Φ(z_α/√VIF) rather than α.






  
Key takeaways

  
Think of the cost of a design as N × (c + k): every LLM response costs one unit, and each query additionally costs c units to obtain (recruiting a user, collecting a representative query, setting up its evaluation). For example, c = 5 means that obtaining one new query costs as much as generating and rating five responses.

  
    
    
  1. When responses are the only cost (c = 0), spend the budget on queries, not on additional responses per query. For a fixed number of rated LLM responses, k = 1 maximises power under every distribution of query difficulty, because VIF ≥ 1.
    2. 
    
  2. When k = 1, the Wilson score test is valid regardless of ρ. Each query-response pair is then an independent observation with probability p; nothing needs correcting.
    3. 
    
  3. When k > 1, the uncorrected Wilson score test is invalid when query difficulty is U-shaped. Its type I error rate is 1 − Φ(z_α/√VIF): with k = 5, a nominal 5% test runs at 6.7% when ρ = 0.05 but at 17% when ρ = 0.5. When difficulty is Unimodal or J-shaped (ρ ≲ 0.05) the inflation is modest.
    4. 
    
  4. When each new query carries a fixed overhead (c > 0), adding responses per query increases power only when that overhead is large and query difficulty is Unimodal or J-shaped (low ρ). With U-shaped difficulty (ρ ≥ 0.5), one response per query remains the best or nearly the best design even when a query costs as much as twenty responses.
    5. 
  






  
Choosing ρ

  
ρ is the correlation between the ratings of two LLM responses to the same query — equivalently, the share of rating variance attributable to differences in query difficulty. For a Beta(a, b) distribution of query-wise acceptability probabilities, ρ = 1/(a+b+1).

  

    
ρ = 0
Every query equally difficult. Pure Binomial; rarely realistic.

    
ρ ≈ 0.02–0.1 (Unimodal or J-shaped)
Difficulty varies but most queries have acceptability probabilities near the overall proportion. Beta(38, 2) gives ρ = 0.02; Beta(19, 1) gives ρ = 0.05.

    
ρ ≥ 0.5 (U-shaped)
Most queries are consistently acceptable or consistently unacceptable. Beta(0.95, 0.05) gives ρ = 0.5. Typical when the LLM-based system is highly consistent and rating is strict.

  

  
With pilot data containing k responses per query, ρ can be estimated by fitting a Beta Binomial model (e.g., glmmTMB in R, family = betabinomial; ρ̂ = 1/(1 + φ̂) where φ̂ is the estimated precision).[7] When uncertain, plan with a larger ρ; it is the conservative choice.






  
Assumptions

  

    
Every query receives the same number of responses k.
With unequal k, use the harmonic mean of k; the result is slightly conservative.

    
LLM responses to the same query are independent given the query.
Shared conversation history or caching makes responses more alike than ρ allows and understates the true VIF.

    
ρ is a planning constant.
The analysis of the collected data should estimate ρ (e.g., a Beta Binomial GLMM); realised power is then somewhat below the planned value. Set the target power a few points above the minimum required.

    
The effective sample size is large enough for the normal approximation.
Require N·k·(1 − p₀)/VIF ≥ 10 — for p₀ = 0.90, at least 100 effectively independent query-response pairs (N × k / VIF). Below roughly 60, a Beta Binomial GLMM fitted to the collected data becomes markedly conservative and often fails to converge.

    
The other one-sample assumptions still apply — except independence of LLM responses.
One binary reference label per LLM response, queries independently and randomly drawn from the population of potential queries, N fixed in advance, a one-sided threshold test as the primary analysis. The one-sample tab requires every query-response pair to be independent; this tab replaces that requirement with the weaker one above — responses need only be independent given their query, with the dependence among responses to the same query captured by ρ and absorbed into VIF.
