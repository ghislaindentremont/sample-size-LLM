Analytic vs. Monte Carlo: what the calculator actually does

  
When you run a Monte Carlo simulation to estimate power — drawing thousands of random samples and counting how often the test rejects — you are approximating a number that can be computed exactly. This calculator computes that number directly, without any simulation.

  
For the Clopper-Pearson exact method, the calculation is genuinely exact. The critical count c is the smallest integer such that P(X ≥ c | Bin(N, p₀)) ≤ α, found by summing exact binomial probabilities. Power is then P(X ≥ c | Bin(N, p₁)), also an exact sum. In R this is one line: 1 - pbinom(c - 1, N, p1). The Monte Carlo simulation, if run long enough, converges to this same number — the analytic formula simply skips the simulation and gives it directly.

  
For the Wilson score method, the analytic formula is a normal (CLT) approximation to the same quantity. The sample size formula is

  
N = ⌈ ( z_α · √(p₀q₀) + z_β · √(p₁q₁) )² / (p₁ − p₀)² ⌉

  
and the power formula at a given N is

  
power = Φ( ( (p₁ − p₀) · √N  −  z_α · √(p₀q₀) ) / √(p₁q₁) )

  
A simulation using the Wilson score CI will converge to a slightly different value, because the actual Wilson CI is discrete (it tests an exact count), while the formula above treats the problem continuously. The gap is typically 1–3 percentage points for the sample sizes relevant to LLM evaluation. When in doubt, the CP exact method requires no approximation and should be preferred.

  
Why not just simulate? Simulation with 10 000 replicates has a standard error of roughly √(0.8 × 0.2 / 10 000) ≈ 0.4 pp near 80% power. The analytic formulas are exact (CP) or have negligible error (Wilson) and run in milliseconds. Simulation is valuable for validating a specific test implementation; the analytic formulas are the right tool for planning.






  
Why pwr.p.test() gives a different answer

  
The pwr package in R uses Cohen's h, an arcsine-transformation effect size:

  
h = 2 · arcsin(√p₁) − 2 · arcsin(√p₀)

  
and the sample size formula N = ⌈(z_α + z_β)² / h²⌉. For p₀ = 0.90, p₁ = 0.95, α = 0.05, one-sided, this gives N = 167.

  
However, at N = 167, the Wilson score test achieves only 75.8% power and the CP exact test achieves 78.4% power — not the 80% that was targeted. The correct sample sizes using Wilson and CP are N = 184 and N = 179 respectively.

  
The arcsine approximation underestimates the required sample size when p is far from 0.5. It was designed as a variance-stabilizing transformation and works well near p = 0.5, but it becomes increasingly inaccurate as p approaches 0 or 1. For proportions above 0.90, the Wilson or CP formulas should be used.

  
If you ran a simulation at N = 167 and observed power near 78%, that simulation was correctly reflecting that N = 167 is underpowered for the Wilson and CP tests at the 80% target. The pwr result was the source of the discrepancy, not the simulation.






  
Which method to report

  
For clinical or regulatory submissions, the CP exact method is preferred because the type I error is guaranteed to be at or below the nominal α — there is no approximation. The achieved α is typically slightly below the nominal (e.g., 4.9% instead of 5%), which is conservative. For general planning where a closed-form formula is needed (e.g., to present sample size derivation in a grant), the Wilson score method is the standard modern choice; it is uniformly better than the arcsine method for proportions near the boundaries.






  
Assumptions

  

    
Responses are independent.
Each judgment is a separate, independent Bernoulli trial. Multiple responses to the same prompt, or multi-turn conversations, violate independence and reduce effective N below the nominal count. Use the Beta-Binomial calculator if responses are clustered by question.

    
The rubric is fixed before data collection.
Acceptable/not-acceptable criteria are defined and locked before any responses are seen. Post-hoc rubric changes make the observed rate uninterpretable.

    
Prompts are a representative sample from the target population.
If your prompts are easier or differently distributed than real-world queries, the estimated rate applies to your prompt set, not deployment traffic.

    
N is fixed before data collection.
Sequential stopping rules or interim analyses alter the type I error unless explicitly accounted for.

    
Judgments are accurate.
Rater disagreement or lenient grading shifts the observed proportion. Measure and report inter-rater agreement separately.
